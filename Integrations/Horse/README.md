# SwagDoc for Horse

Middleware that publishes the document generated by SwagDoc and a Swagger UI page in an API written with the
[Horse](https://github.com/HashLoad/horse) framework.

The document is described with the objects of SwagDoc, so the same API can be published as an OpenAPI 3 or as a
Swagger 2.0 document by changing the `SpecVersion` property.

Applications that document their API with GBSwagger are migrated by the
[migration guide](Migration-gbswagger-to-SwagDoc.md).

## Requirements

- Delphi XE7 or newer. Lazarus is not supported, because SwagDoc is written for the Delphi RTL.
- Horse 3.3.7 or newer.

## Installation

Add the following folders to the library path or to the search path of the project:

```
SwagDoc\Source
SwagDoc\Integrations\Horse\Source
```

## Quick start

```delphi
uses
  Horse,
  Horse.SwagDoc;

begin
  THorse.Use(HorseSwagDoc);

  SwagDocApi.Info.Title := 'Pet Store';
  SwagDocApi.Info.Version := '1.0.0';

  THorse.Get('/pets/:id',
    procedure(Req: THorseRequest; Res: THorseResponse)
    begin
      Res.Send('{}');
    end);

  THorse.Listen(9000);
end.
```

The Swagger UI page is published in `http://localhost:9000/docs` and the document in
`http://localhost:9000/docs/openapi.json`.

## Documenting an operation

The `Route` method translates a Horse route to a path of the document, adding a parameter for each variable of
the route. The path is a `TSwagPath`, so the whole model of SwagDoc is available to describe the operation.

```delphi
uses
  Horse.SwagDoc,
  Swag.Common.Types,
  Swag.Doc.Path.Operation,
  Swag.Doc.Path.Operation.Response;

var
  vOperation: TSwagPathOperation;
  vResponse: TSwagResponse;
begin
  vOperation := SwagDocApi.Route('/pets/:id').AddOperation(ohvGet);
  vOperation.OperationId := 'getPet';
  vOperation.Summary := 'Returns a pet';
  vOperation.Tags.Add('Pets');

  vResponse := TSwagResponse.Create;
  vResponse.StatusCode := '200';
  vResponse.Description := 'Successful response';
  vOperation.Responses.Add(vResponse.StatusCode, vResponse);
end;
```

## Discovery of the registered routes

When the document is generated, the routes registered in Horse that are not documented yet are added to it with
a single response and without a summary, which shows the endpoints of the API that still need documentation.
The router only knows the path and the HTTP method of a route, so everything else must be documented by the
application. The discovery is disabled with:

```delphi
SwagDocConfig.DiscoverRoutes := False;
```

## Settings

The settings must be defined before the middleware is added to the application, because the routes of the
document and of the page are registered at that moment.

```delphi
SwagDocConfig.UserInterfaceRoute := '/api-docs';
SwagDocConfig.DocumentRoute := '/api-docs/swagger.json';
SwagDocConfig.UserInterfaceTitle := 'Pet Store';
SwagDocConfig.UserInterfaceResources := '/swagger-ui';
SwagDocConfig.DiscoverRoutes := False;

THorse.Use(HorseSwagDoc);
```

The routes of the page and of the document can also be defined by the middleware:

```delphi
THorse.Use(HorseSwagDoc('/api-docs', '/api-docs/openapi.json'));
```

| Property                 | Default value             | Description                                                 |
| ------------------------ | ------------------------- | ----------------------------------------------------------- |
| `UserInterfaceRoute`     | `/docs`                   | Route of the page                                            |
| `DocumentRoute`          | `/docs/openapi.json`      | Route of the generated document                              |
| `UserInterface`          | `uiSwaggerUi`             | Interface that renders the document: `uiSwaggerUi`, `uiScalar` |
| `UserInterfaceTitle`     | The title of the document | Title of the page                                            |
| `UserInterfaceResources` | Embedded files or a CDN   | Base address of the files of the interface                   |
| `DiscoverRoutes`         | `True`                    | Documents the registered routes that are not documented yet  |

## Swagger 2.0

The document created by the middleware is written as an OpenAPI 3 document. Applications that publish a
Swagger 2.0 document define the specification version and usually change the route of the document:

```delphi
SwagDocConfig.DocumentRoute := '/docs/swagger.json';
THorse.Use(HorseSwagDoc);

SwagDocApi.SpecVersion := svSwagger2;
```

## User interface

The document is rendered by Swagger UI, the default, or by Scalar:

```delphi
SwagDocConfig.UserInterface := uiScalar;
```

## Where the files of the interface come from

By default the page loads the files of the selected interface from a public CDN, so nothing is embedded in the
executable. There are two other ways to publish them.

**Embedded in the application.** Declare the conditional define of the interface in the options of the project,
under *Conditional defines*, and the files are linked into the executable and published under the route of the
page. They are embedded compressed with gzip and decompressed once, on the first request of each file.

| Conditional define                   | Interface  | Size added to the executable |
| ------------------------------------ | ---------- | ---------------------------- |
| `HORSE_SWAGDOC_EMBEDDED_SWAGGER_UI`  | Swagger UI | about 510 KB                 |
| `HORSE_SWAGDOC_EMBEDDED_SCALAR`      | Scalar     | about 1 MB                   |

Both defines can be declared together, and the interface is still selected at runtime. When the selected
interface is not the embedded one, its files are loaded from the CDN. The licenses of the embedded files are in
the `Resources` folder and must be kept with the distribution of the application.

**Published by the application.** Copy the files to a folder served by a static file middleware and point the
settings to it:

```delphi
SwagDocConfig.UserInterfaceResources := '/swagger-ui';
```

## Using a document built by the application

Applications that already build their own document give it to the middleware, which does not destroy a document
that it does not own:

```delphi
SetSwagDocApi(fSwagDoc);
```

## Generation of the document

The document is generated on the first request and kept in memory. Applications that change the document while
they are running discard the generated one with:

```delphi
ClearSwagDocApiCache;
```
